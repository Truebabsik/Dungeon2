# Ограничения работы: читать ПЕРЕД задачей

Этот файл — общая часть всех брифов. Он не дублируется в брифах: бриф ссылается на него и содержит
только специфику задачи. Меняешь правило — меняешь здесь, и оно меняется для всех задач сразу.

---

## 1. Соглашения кода

**Область действия:** действуют всегда. Проект — Godot 4.7.2 в `game/` (`game/project.godot`),
GDScript живёт в `game/level/`, `game/tests/`, `game/tools/`.

1. **Вердикт — код возврата процесса.** `quit(0)` зелёно, `1` провал, `2` сломан приговор.
   **Текст в stderr вердиктом не является:** Godot пишет туда безобидный шум (`user://logs/...`,
   `Failed to read the root certificate store`) даже при коде 0. В этом проекте stderr уже дважды скрывал
   реальный дефект при зелёном прогоне — не полагайся на него.
2. **Никаких `class_name` в GDScript проекта** (`game/level/`, `game/tests/`, `game/tools/`) — только
   `const X := preload("res://...")`. `class_name` не резолвится в headless-прогоне без обновления кэша
   редактора.
3. **Имя константы `preload` не совпадает с классом движка:** `const Window := ...` — жёсткая ошибка разбора
   (`shadows a native class`). Модуль окна подключён как `WindowScript`.
4. **Логика без нод:** скрипты, не привязанные к сцене, — только `RefCounted`, ни `Node`, ни `SceneTree`,
   ни сцен. (Структурных папок `game/sim/`, `game/content/` в текущей раскладке нет; правило действует
   для любого нового скрипта чистой логики.)
5. **Отступы — табы.** Идентификаторы английские, комментарии и имена тестов русские.
6. **Детерминизм:** обход в фиксированном порядке (по массивам или сортировке по id), никаких решений,
   зависящих от порядка словаря. Единственный источник случайности — `rng`, засеянный из `config.seed`.
7. **Типизация:** объекты из `preload`-константы — через `:=`; из функций без аннотации возврата — через `=`
   и динамический доступ; невыводимый тип — явной аннотацией (`: Variant`).
8. **Ворота — `failed: 0`, а не общее число проверок.** Число растёт с каждым кейсом, фиксировать его
   в ожиданиях нельзя.

## 2. Команды гейта

**Гейт проекта — одна команда:**

```
Godot/Godot_v4.7.2-stable_win64_console.exe --headless --path game --script res://tests/level_check.gd
```

Вывод: строки `ok: ...` 和 `ПРОВАЛ ...`, итог `ok: <N>` / `failed: <M>`, код возврата — вердикт (§1.1).
Ожидаемое значение `failed` называет бриф; самовольно не ослабляй проверки и не «чини» чужие провалы
вне своей области (§4).

**Импорт ассетов.** После замены ассетов в `game/assets/` сначала прогоняй импорт:

```
... --headless --path game --import
```

Гейт без `--import` читает устаревший импорт-кэш: проверки будут сверять старый ресурс и «зеленеть»
или краснеть неверно.

**Blender 5.2:** `"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" -b --python <скрипт.py>`;
аргументы скрипту — после `--`.

**Временные пробы и логи** — только внутри проекта: `docs/current/<задача>/temp/`, удалить после задачи.
**Запрещено работать вне папок проекта** (`E:\Temp\`, `C:\Temp\`, `%TEMP%` и т.д.) — все временные файлы
только внутри проекта, в папке текущей задачи.

Скрипты `preflight`, `run.gd`, `run_red.gd` из других проектов здесь не существуют — не ссылайся на них.

## 3. Грабли среды (headless Godot, PowerShell 5.1)

- **`calc_loop_triangles()` висит в headless-прогоне** — не использовать; треугольники бери через
  `surface_get_arrays`.
- **`await process_frame` в скрипте-наследнике `SceneTree` — дедлок.** Вся работа и печать — в первом
  `_process`; `print` в `_initialize` теряется.
- **Код возврата 0 не означает чистый лог.** `ERROR:`/`SCRIPT ERROR:` в логе при зелёном коде — ложный
  зелёный: лог читается целиком, а не только итоговая строка. Класс зафиксирован в `review-checklist.md`.
- **PowerShell 5.1:** `>` пишет вывод в UTF-16, `Tee-Object` без `-Encoding` — в кодировке консоли.
  В файл — `Out-File -Encoding utf8` (или `| Out-File -FilePath ... -Encoding utf8`); читать через
  `Get-Content -Encoding utf8` или `Select-String -Path`.
- Кириллица в прямом выводе консоли PowerShell может отображаться кракозябрами — на содержимое это не
  влияет, сравнивай через файл, а не глазами по консоли.

## 4. Область работы

Бриф всегда называет, что можно править. По умолчанию:

- **Не трогай то, что прошло ревью** без прямого указания: любая правка там расширяет область ревью.
- **Нашёл дефект вне своей области** — опиши в отчёте, не правь.
- **Коммит делает ведущий.** Исполнитель и ревьюер оставляют изменения в рабочем дереве.
- Не создавай файлы вне указанных путей; временные пробы убирай за собой.
