# Чек-лист ревьюера

## Формат вердикта ревьюера

```
гейт: level_check.gd — ok <N>, failed <M>, код <0|1>
по каждому пункту задания: ADDRESSED | NOT ADDRESSED — одной строкой, с файл:строка
находки: Critical <N>, Important <N>, Minor <N> — по одной строке
assessment: <Да | Нет | С правками> + 1–2 фразы
отчёт: <путь к файлу>
```

Полные таблицы, переборы и транскрипты проб — **в файл отчёта**, не в ответ (см. `report-contract.md`).

## Перечень классов дефектов

Ревью ищет в первую очередь классы, уже встречавшиеся в проекте:

1. **Ложно-зелёный прогон:** код возврата 0, но в логе `ERROR:` / `SCRIPT ERROR:`. Лог читается целиком,
   а не только итоговая строка (см. `constraints.md` §3).
2. **Проверка по устаревшему артефакту:** числа, меш или импорт-кэш от старой версии ресурса. После
   замены ассета нужен прогон с `--import` (`constraints.md` §2), иначе гейт сверяет не то.
3. **Отчёт заявлен, файл отсутствует:** путь из отчёта обязан существовать на диске; ссылка на
   несуществующий отчёт — блокер вердикта.
4. **Заявленные числа не воспроизводятся:** размер, треугольники, координаты из отчёта перепроверяются
   собственным прогоном ревьюера; расхождение — Important.
5. **DRY, слои и рамки брифа:** дублирование логики, нарушение разделения слоёв (`constraints.md` §1 п.4),
   правки не по брифу (`brief-template.md` п.5).

**Запрещено ревьюеру:** возвращать отчёт целиком в контекст ведущего; писать «выглядит хорошо» без проб;
давать отзыв о коде, который не читал; помечать придирки как Critical; уходить от вердикта. Субагентов
не вызывать — всё делаешь сам.
