## Где это в проекте

Сейчас уровень собирается в рантайме: `game/level/level_builder.gd` читает `MODULES` из `game/level/level_map.gd`
(285 записей) и создаёт инстансы в `_ready()`. Пользователь хочет **редактируемую сцену**: модули — обычные узлы в
`level.tscn`, их можно двигать в редакторе Godot. Решение пользователя перекрывает прежний вариант «данные в коде».
Свет, `WorldEnvironment`, `Camera3D` в `level.tscn` **не меняются**.

## Что сделать

1. **Одноразовая конвертация.** Временный headless-скрипт в `E:\Temp\opencode\t11_convert.gd` (вне `game/`), запускается
   через `--script`, пока `level_map.gd` и `level_builder.gd` ещё существуют. Он:
   - загружает `res://level/level.tscn`, создаёт `level_builder` через `build()` и для каждого созданного инстанса
     делает `owner` = корень сцены, имя узла `<kind>_<NNN>` (NNN — порядковый номер с 001, по порядку `MODULES`);
   - корню `Level` снимает скрипт (`set_script(null)`), чтобы `_ready()` не создавал модули повторно;
   - сохраняет результат в `res://level/level.tscn` через `PackedScene.pack` + `ResourceSaver.save`.
   Ожидаемо: в сцене 285 детей-инстансов `Level`, каждый — инстанс `res://assets/kaykit/<kind>.gltf`
   (в `.tscn` это `[node ... instance=ExtResource(...)]`). Позиция и поворот — те же, что давал билдер.
   Света, камеры и окружения не трогать: они остаются как были.
   Если `pack` не сохраняет инстансы как внешние сцены, а разворачивает их в узлы — остановиться и вернуть `NEEDS_CONTEXT`.
2. **Прототипы.** В `level.tscn` добавить узел `Prototypes` (`Node3D`) как дочерний **корня сцены** `Level`, а не модулей уровня.
   Позиция `Vector3(-20, 0, 0)`. Модули уровня — дети `Level` с `scene_file_path`, прототипы — только внутри `Prototypes`.
   Внутри — по **одному** инстансу каждого `kind`, который используется в уровне (14 видов). Имя `<kind>`,
   позиция `Vector3(0, 0, i * 6)` (i — 0..13), поворот 0. Прототипы стоят вне плана уровня (план начинается с x ≈ −4 м).
3. **Удалить** `game/level/level_builder.gd` и `game/level/level_map.gd`: сцена становится единственным источником.
   Перед удалением убедиться, что на них больше нет ссылок в `game/` (кроме `level_check.gd`, который переписывается).
4. **Переписать** `game/tests/level_check.gd` под сцену (без `MODULES`, без `preload` удалённых файлов). Проверки:
   1. сцена `res://level/level.tscn` загружается; корень `Level` существует;
   2. у `Level` есть хотя бы один дочерний узел-инстанс модуля (кроме `Prototypes`, света и камеры); каждый такой узел
      имеет `scene_file_path` вида `res://assets/kaykit/<kind>.gltf`, и файл существует;
   3. узел `Prototypes` существует, у него ровно по одному дочернему инстансу на каждый `kind`, встречающийся в модулях
      уровня (сравнение множеств, не число);
   4. `Prototypes` лежит вне плана: `position.x < -10`; модули уровня не являются потомками `Prototypes`;
   5. камера (`Camera3D`) и `WorldEnvironment` присутствуют в корне.
   Без жёстко заданных чисел (285 и 14 в скрипте не фиксировать: сцену будут редактировать). Вывод `failed: N`.
   Коды: `quit(0)` — `failed == 0`; `quit(1)` — `failed > 0`; `quit(2)` — сцена не загрузилась или скрипт упал.
   Табы, без `class_name`, `const X := preload(...)` для ссылок.
5. Не менять `project.godot`, `assets/**`, `art/**`, `docs/**` кроме отчёта.
