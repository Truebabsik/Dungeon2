## Что сделать

### 1. `game/level/level_map.gd`

- `const CELL_SIZE := 4.0`
- `const MODULES: Array = [...]`. Каждый элемент — `{ "kind": String, "cell": Vector2i, "rot": int }`.
  `kind` — имя `.gltf` без расширения из `game/assets/kaykit/`. `rot` — только 0, 90, 180 или 270.
- Раскладка: по `art/reference/reference.png` перенеси в `MODULES` основные структуры плана — комнаты (пол и стены), проёмы,
  лестницу, колонны и крупный реквизит. Сетка: клетка 4 м. Оси: `cell.x` — вправо, `cell.y` — вниз по плану.
  Точность — приблизительная; сверку с референсом сделает задача 5. Не пытайся переносить каждый пиксель.
- Использовать только `kind` из списка задачи 1. Если для раскладки нужна модель вне списка — не выдумывать её,
  а вернуть `NEEDS_CONTEXT` с перечнем.

### 2. `game/level/level_builder.gd`

- Класс `extends Node3D`, без `class_name`. Модули загружать через `const`/`preload`, не через строки в `load()`
  в цикле, если это не нужно. Допустимо `load("res://assets/kaykit/%s.gltf" % kind)`.
- Метод `func build() -> int`: для каждой записи создаёт инстанс модели, добавляет как потомка, возвращает
  число успешно созданных.
- Позиционирование (геометрия проверена по файлам: стена `x -2..2, y 0..4, z -0.5..0.5`; пол `4×4` с центром в origin):
  - пол (`floor_*`): `Vector3(cell.x*4 + 2, 0, cell.y*4 + 2)`, поворот `rot` по Y;
  - стена (`wall*`): `rot == 0` — вдоль X на северной грани клетки: `Vector3(cell.x*4 + 2, 0, cell.y*4)`;
    `rot == 90` — вдоль Z на западной грани: `Vector3(cell.x*4, 0, cell.y*4 + 2)`; поворот `rot` по Y;
  - прочее (реквизит, лестницы, колонны): центр клетки `Vector3(cell.x*4 + 2, 0, cell.y*4 + 2)`, поворот `rot` по Y.
- Невалидный `rot` или неизвестный `kind`: `push_error(...)`, запись пропускается, в счёт не входит.
- Все константы (`4`, `2`) вынести в именованные константы файла, их значения из `level_map.gd` (`CELL_SIZE`).
