## 3. Расчёт камеры

Камера: `rotation_degrees = (-35, 45, 0)`, ортографическая, экран 1152×648 (соотношение 16:9).
Базис: right = (0.7071, 0, −0.7071); up = (−0.4056, 0.8192, −0.4056).
Координаты: R = 0.7071·(x − z), U = −0.4056·(x + z) + 0.8192·y.

**Ширина (R).** Крайние точки по `x − z` (с учётом толщины стены 0.5 м):
- максимум 56.5 — северо-восточный угол клетки (13, 0): x = 56, z = 0;
- минимум −32.5 — юго-западные углы клеток (2, 9) (x = 8, z = 40) и (4, 11) (x = 16, z = 48).
Размах 89 м → 0.7071·89 = 62.9 единицы. Ширина кадра в единицах = `size` · 16/9.
Доля: 62.9 / (41 · 16/9) = **86.3 %** (требование ≥ 85 %).

**Высота (U).** Стены высотой 4 м поднимают верх плана на 0.8192·4 = 3.28.
- низ: максимум `x + z` = 96.5 у клетки (13, 9) (юго-восточный угол) и 96 у клетки (12, 10) → U = −39.14;
- верх: минимум `x + z` = 7.5 у клетки (0, 2) (северо-западный угол, с толщиной стены) → U = −3.04 + 3.28 = +0.24.
Размах 39.4 единицы. Кадр по высоте должен быть не меньше 39.4: при `size` = 40 поле ≈ 0.3 единицы сверху и снизу, при 41 — ≈ 0.8.

**Центр.** R_mid = 0.7071·12 = 8.49; U_mid = (−39.14 + 0.24)/2 = −19.45.
Позиция камеры при y = 40: `x + z = (19.45 + 0.8192·40) / 0.4056 = 128.75`, `x − z = 12` → x = 70.38, z = 58.38.

**Выбор `size` = 41 — запас, а не минимум.** Значение 40 по расчёту тоже влезает: ширина 88.5 %, поле по вертикали ≈ 0.3 единицы сверху и снизу. Выбрано 41 для большего поля (ширина 86.3 %, ≥ 85 % по брифу). Расчёт для 40 не проверен рендером с финальной позицией камеры.
Первый проход (`size = 40`, позиция (72.36, 40, 60.36)) показал обрезку верха плана на скриншоте. Причина — позиция камеры (центр кадра сдвинут относительно плана), а не размер; позиция исправлена на (70.38, 40, 58.38).

Кадрирование на скриншоте: план по горизонтали x ≈ 80…1073 (86.2 %), по вертикали y ≈ 14…632, центр кадра (576, 324) — центр плана (576, 323).

- **Шапка `level_map.gd`: решение ведущего.** Бриф разрешал править только `MODULES`. - **Секционные комментарии в `MODULES`** (`# Пол`, `# Стены и проёмы`, `# Лестницы, колонны, реквизит`) убраны: генератор писал список без них. Порядок записей тот же: полы, стены rot 0, стены rot 90, реквизит.

- **Проёмы и перегородки.** Прежняя карта имела 14 `wall_doorway`, новая — 2; новый план без внутренних перегородок. Это упрощение. Возможная следующая итерация — ввести перегородки в план.
