## 2. Формула

Позиция = центр клетки `origin + (HALF, 0, HALF)` + `R(rot) · (0, 0, −STAIRS_DEPTH/2)`.

- `rot 0`: смещение `(0, 0, −2)`.
- `rot 90`: смещение `(−2, 0, 0)`. Проверено прогоном: `Vector3(0,0,-2).rotated(UP, 90°)` даёт `(−2, 0, 0)`, то есть совпадает с тем же правилом, что `rotation_degrees.y = rot` у модели.

Почему так: модель имеет начало на задней кромке (z 0…4), а клетка центрирована. Смещение `−depth/2` ставит глубину модели ровно на клетку. Константа `2` выражена как `STAIRS_DEPTH * 0.5`, литерала `2` в формуле нет. Константа `4` — `STAIRS_DEPTH`.

## 4. Доказательство позиции (проба)

Проба `t8_probe.gd` (удалена после прогона) вызывала `level.tscn`, `build()` и для каждого узла `stairs` брала AABB мешей, приведённые к системе уровня (уровень с единичным преобразованием, поэтому позиция узла = мировая).

Дословный вывод:

Таблица границ:

| `(12, 7)` | 0 | (50, 0, 28) | z ∈ [28.000, 32.000] | z ∈ [28, 32] ✓ | x ∈ [47.5, 52.5] |

Ширина выходит за клетку на 0.5 м с каждой стороны. Задача это не требовала менять, отмечаю в разделе 6.

## 6. Что заметил и не стал делать

- Ширина модели лестницы 5 м при клетке 4 м. Смещение по поперечной оси не корректировалось (ни по `x` для `rot 0`, ни по `z` для `rot 90`): бриф это не требовал. Если нужно, лестница `(12,7)` выходит на 0.5 м за границы клетки по x (47.5…52.5 при клетке 48…52). Решение за ведущим.
- Узлы созданы без имени по модели: один назван `stairs2`, другой `@Node3D@272`. Для поиска в тестах по имени не годится, пробе пришлось опираться на порядок в `MODULES`. Отдельно не чинил.
- Проба не использовала глобальные преобразования: `global_transform` до добавления в дерево вернул нули, поэтому брала локальные по цепочке до уровня. Для уровня с единичным преобразованием результат тот же.
- Экран T7-скриншота и T8 не сравнивались попиксельно. Оценка в разделе 5 качественная.
