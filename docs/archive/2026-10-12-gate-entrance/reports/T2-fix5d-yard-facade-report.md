## 2. Как устроено решение

**Двор.** Узел `Yard` — `StaticBody3D` c `transform` origin `(11, −0.2, 0)` и коллизией 8×0.4×8
(мир x 7…15, верх 0). Визуальная поверхность сделана **двумя** BoxMesh под этим телом, потому что
пункты брифа конфликтуют: «верх ровно y=0» + «не создавать наложение второй поверхностью на ту же
плоскость». Пол-диск пещеры r=7.2 перекрывает полосу x 7.0…7.2 двора — **31 грань диска** лежит на
плоскости y=0 в зоне коробки (площадь наложения ≈ 0.44 м², интеграл кругового сегмента 7.0…7.2).
Поэтому:
- основная плита x 7.2…15 (начинается ровно у края диска), верх гранью **y = 0** — под ней нет второй
  поверхности (касание диска по x=7.2 — только точка z=0, не площадь);
- кромка x 7.0…7.2, верх **y = −0.001** — на 1 мм ниже диска, т.е. внахлёст с ним не копланарна
  (z-fighting невозможен), и закрывает угловые вырезы между диском и коробкой коллизии.

**Фасад.** `FACADE_THICK = 0.08` при `FACADE_X = 6.5` → панель обшивки x 6.5…6.58. Замерена не на глаз:
плоскость 6.58 содержит 15 вершин обшивки, плоскости 6.9 (прежняя передняя грань) — 0.
Ноги арки (мир x 6.063…6.917) выступают за панель на 0.3373 м — с двора читаются как арка.

**Методика замеров** (временная проба `fix5d_measure.gd`, удалена): окно обшивки x≥6.45, |z|≥1.9,
y≤5.05 **без плоских граней пола** (max_y≤0.05 — иначе пол-диск z=0 даёт ложный максимум x=6.77);
мировые AABB считаются по цепочке предков (в `_initialize` сцена ещё не в дереве, `global_transform`
недоступен — по этой и по «пустой AABB съедал начало координат» пробе чинилась дважды, чужие файлы
не затронуты).

## 4. Решения вопреки брифу

1. **Двор — два меша, а не один «того же габарита»** (буквально бриф: предпочтительно один BoxMesh с
   верхом ровно y=0). Один меш 8×0.4×8 с верхом 0 давал бы копланарное наложение с пол-диском на
   31 грани / ≈0.44 м² — то самое z-fighting, которое бриф запрещает во втором подпункте. Разделение
   (основная плита с верхом 0 + кромка с верхом −0.001) выполняет оба требования одновременно;
   чеки гейта (`верх двора 0.0000`, `MerchantSpot`) зелёные.
2. **Зазор решётка–обшивка дан двумя числами** (0.3676 до панели 6.58 и 0.1781 до ближайшей
   геометрии оболочки 6.7695): в окне замера есть скальный выступ оболочки у основания ног арки,
   который к `FACADE_THICK` не относится. Оба числа положительны — решётка ничего не задевает.

## 5. Замечания (не делал, вне области)

- **Розовые клинья у основания ворот с двора** (в кадре: земля x ≈ 6.04…6.95 вне диска r=7.2 при
  |z|>1.7 и вне коробки двора x≥7) — дыра между краем диска и началом двора. Вне области задачи:
  габарит двора задан коллизией и чекой `верх двора 0.0000`, расширять — отдельное решение.
- **Верх проёма изнутри — фон за краем двора** (двор 8 м глубиной, линия горизонта ниже верха
  проёма). Приёмка «за решёткой видна поверхность двора (а не фон)» выполнена для нижней части
  проёма; полностью закрыть фон может только более глубокий двор/продолжение зоны.
- Два magenta-пятна в своде купола на кадре с двора — световые колодцы (шахты `cut_wells`), к воротам
  не относятся.
- Свет капчера воссоздан по описанию из отчёта 5c (исходный капчер предыдущим прогоном был удалён) —
  параметры совпадают, но это реконструкция, не оригинал скрипта.
- `scripts` Godot `.godot/uid_cache` хранит uid удалённых проб — безвредно, пересборка не требуется.
