# Отчёт T20: коллизии из сетки и модулей (ревизия 2: высоты по визуалу)

Статус: DONE_WITH_CONCERNS (см. «Что заметил»: uid скрипта не создан; пол не «тонкий», толщина берётся из тайлов).

Ревизия 2 исправляет Critical из ревью: в ревизии 1 коробки стен и пола стояли по захардкоженной высоте, не совпадая с визуалом (пол `y = 0`, стены `y ∈ [0, 4]`). Теперь все высоты берутся из данных сцены.

## 1. Что изменено

- `game/level/grid_collision_builder.gd` (новый, `extends Node`, без `class_name`):
  - `_ready` → `build()`. `build()` создаёт контейнер `Collision` (Node3D, единичный transform, под `GridCollision`), затем стены, пол, модули. Повторный вызов `build()` не предусмотрен: `old.free()` удалён (ревизия 1, Minor).
  - `cell_visual_box(grid, cell)` (строки 33–36): визуальный AABB ячейки в координатах Level = `(grid.transform * Transform3D(rot, grid.map_to_local(cell))) * item_mesh.get_aabb()`, где `rot = get_basis_with_orthogonal_index(get_cell_item_orientation(cell))`.
  - `cell_column_center` (строки 39–41): X и Z — центр ячейки из `map_to_local`, Y — центр визуального AABB.
  - `cell_column_size` (строки 44–45): X и Z — `cell_size`, Y — высота визуального AABB тайла.
  - `build_walls` (строки 21–26): `StaticBody3D` `Wall_x_y_z` на каждую ячейку `GridMapWall`, коробка по `cell_column_center`/`cell_column_size`.
  - `build_floor` (строки 28–34): один `StaticBody3D` `Floor` с коробкой на каждую ячейку `GridMapFloor` (276 шейпов).
  - `build_modules` (строки 36–47): без изменений относительно ревизии 1. Модули: AABB мешей в координатах Level.
- `game/level/level.tscn`: без изменений относительно ревизии 1 (ext_resource `29_gridcol` без uid, узел `GridCollision`).
- `design.md`: пункт 9 в «Решениях» — GridUpper без коллизий.

Почему так, а не через глобальный bake-AABB: `get_bake_meshes()` даёт границы по всем элементам сетки сразу. Для пола общий низ — 1.0, верх — 2.29: это объединение разных тайлов. Ячейка-тайл `103` (основной пол) занимает 1.90…2.05. Одна коробка на всю сетку завысила бы или занизила отдельные тайлы. Поэтому высота берётся по ячейке.

Персонаж стоит на `y = 2.33`: это выше верха пола (2.29), значит нижняя грань не блокирует. Гравитации в дизайне нет, поэтому на движение не влияет.

## 6. Что заметил и не стал делать

- **uid скрипта.** Headless не создаёт `grid_collision_builder.gd.uid`; ext_resource без uid. Godot принимает, uid допишет редактор при сохранении.
- **Пол не «тонкий».** Толщина коробки = высота визуального тайла (0.15 для тайла `103`). Общий верх пола 2.29 — из-за других тайлов пола (элементы выше основного пола). Это по данным сцены, без констант. Если эти тайлы нужны как «ступени», их коллизия корректна; если нет — отдельное решение.
- **Швы пола.** 276 коробок одного тела на одной высоте; швы не должны мешать без гравитации. Проверка швов в движении — в T22.
- **GridUpper без коллизий** — решение записано в design.md, пункт 9.
- **Модули по AABB** — без изменений с ревизии 1 (мелочь: монеты, свечи, бутылка дают коробки 0.1–0.4 м; грубость по риску 2 дизайна).
- **Вне области:** `character_idle.gd` вызывает `get_node("Rig_Medium_General/AnimationPlayer")`; это T21.
- Временные файлы `E:\Temp\opencode\t20*` удалены.
